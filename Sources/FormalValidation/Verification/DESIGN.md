# Verification

## Purpose and Scope
Check explicit finite scalar scenarios on audited generated models. Parent: FormalValidation. No children.

## Responsibilities and Boundaries
Own scenario validation, artifact audit, independent decoding, IR execution, TLC exploration, Lean finite theorems and reports. No compiler dependency and no source semantic certification.

## Architecture
```text
Audited snapshot + typed cases -> IR / bundled TLC / bundled Lean -> scoped report
```

## Contracts and Invariants
Strict schema 1 scenarios provide named entries, scalar argument strings and expected terminal statuses. At most 32 cases, 128 arguments, 256 decimal digits per value, fuel 1...4096 and per-process timeout 1...3600 seconds. Only scalar integer/bits are supported. Artifact bytes are bounded and copied once into private workspaces. Runtime hashes are pinned; independent data decoders must agree with program.json. Never execute user lakefiles or arbitrary property code. TLC must finish, satisfy Expected with TLC built-in deadlock checking enabled (terminal stuttering is generated by the audited wrapper), explore more than one distinct state and reach a terminal state. Lean must kernel-check an expected-outcome theorem whose actual axiom dependencies are a subset of the pinned standard allowlist (propext, Classical.choice, Quot.sound), excluding sorryAx and custom axioms. Evaluation exhaustion is UNKNOWN. MODEL_CHECKED and PROVED describe only named finite cases of the generated model; translation remains UNVALIDATED. Counterexamples exit 5, bounds/timeouts exit 6, integrity exit 4, tool errors exit 7. Each run has a unique directory and report; partial results survive external tool failure.

## Runtime Flows
Load a bounded scenario and audited artifact snapshot, validate typed cases, and create a unique run directory. Compile the audited Lean runtime and program directly. For each case, preflight bounded IR execution, run SANY/TLC and the controlled Lean proof, then collect independent statuses. Bound exhaustion skips model execution and yields UNKNOWN. Save a report atomically after the case loop, including tool failures and cancellation observed by the runner.

## State, Ownership, and Lifecycle
Invocation-local immutable configuration and locally owned temporary files. No shared mutable state. Staging is removed on failure. Completed reports persist in the requested output.

## Failure, Concurrency, and Constraints
Typed errors preserve failure; deadlines, cancellation, and output limits never count as verification success.

## Verification and Change Impact
Tests/FormalValidationTests own scenario/audit rejection. Tools/verify-distribution.py owns real positive, counterexample, bound, relocation and tamper paths. Runtime changes require updating trusted hashes and rerunning both tools.

Verification subprocesses use a 512 MiB monitored workspace budget. Lean is launched with a 1024 MiB memory limit; Java uses a 512 MiB heap and 32 MiB stack. Exceeding these budgets reports UNKNOWN and exit 6.

## Internal Consumers
[Properties](../Properties/DESIGN.md) may consume ArtifactSnapshot’s audited immutable program/files/hashes, ScalarValueRenderer’s exact scalar literals, and LeanProofAudit with an explicit controlled theorem name, plus SANYOutputAudit for parser diagnostics. The default checkedCase audit remains backward compatible. These contracts perform identity/data checks and axiom inspection; they do not establish source semantic preservation.


Finite scenarios may select Number using explicit inputViews/resultView fields; absent views preserve existing integer/bit parsing. Number values accept decimal/special values or exact bits: encodings. Expected Number results compare canonical bits, preserving signed zero. [IR execution](../../FormalIR/Execution/DESIGN.md#binary64-number-contract) owns the meaning.

The binary64 exact-magnitude suite includes exponent alignment across more than 2000 bits. A cold TLC run exhausted 16 MiB stack on maximum-finite addition; the same 144-vector suite completes with 32 MiB. Stack exhaustion is a bounded UNKNOWN, not a semantic result.

ScalarView owns interpretation shared by finite and universal checking. Properties consumes it through the compatible PropertyView alias and owns only its expression-kind mapping. This preserves the component dependency direction.

Each case owns a private Java temporary directory beneath its monitored workspace. SANY/TLC standard-module extraction must not collide with another verification process or host TLC invocation. Concurrent source checks exercise this invariant.


### SANY diagnostic contract
SANYOutputAudit owns the shared interpretation of pinned SANY output. Success
requires process exit zero, an exact semantic-processing line for the requested
module, and no anchored SANY error/fatal diagnostic or Java exception. Paths
containing error or ERROR are ordinary log data. Exit zero alone is insufficient:
SANY may report semantic errors after processing a module and still exit zero.
ModelVerifier and Properties both consume this audit; transport and resource
failures retain their caller-owned typed error handling. VerificationTests owns
positive/path, semantic-error, parse-error, exception and incomplete-output
cases; Tools/verify-number-regressions.py checks actual SANY and finite/universal
CLI runs, including paths containing error.


## Structured evidence change impact
[Inspection](../Inspection/DESIGN.md) and [SDK transition](../../../Documentation/SDK-TRANSITION.md) define the target structured-output/correspondence/graph contract. Preserve this component's actual semantic and trust invariants. Update direct callers/results/resource audits in the same cutover; do not add legacy-report adapters. User Lean elaboration requires its explicit isolation capability; current trusted generated-model tooling is not evidence of safe arbitrary Lean execution.
