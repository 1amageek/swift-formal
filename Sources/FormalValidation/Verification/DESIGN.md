# Verification

## Purpose and Scope
Check explicit finite scalar scenarios on audited generated models. Parent: FormalValidation. No children.

## Responsibilities and Boundaries
Own scenario validation, artifact audit, independent decoding, IR execution, TLC exploration, Lean finite theorems and reports. No compiler dependency and no source semantic certification.

## Architecture
```text
Audited snapshot + typed cases -> IR / bundled TLC / bundled Lean -> scoped report
```

## Contracts and Invariants
Strict schema 1 scenarios provide named entries, scalar argument strings and expected terminal statuses. At most 32 cases, 128 arguments, 256 decimal digits per value, fuel 1...4096 and per-process timeout 1...3600 seconds. Only scalar integer/bits are supported. Artifact bytes are bounded and copied once into private workspaces. Runtime hashes are pinned; independent data decoders must agree with program.json. Never execute user lakefiles or arbitrary property code. TLC must finish, satisfy Expected with TLC built-in deadlock checking enabled (terminal stuttering is generated by the audited wrapper), explore more than one distinct state and reach a terminal state. Lean must kernel-check an expected-outcome theorem whose actual axiom dependencies are a subset of the pinned standard allowlist (propext, Classical.choice, Quot.sound), excluding sorryAx and custom axioms. Evaluation exhaustion is UNKNOWN. MODEL_CHECKED and PROVED describe only named finite cases of the generated model; translation remains UNVALIDATED. Counterexamples exit 5, bounds/timeouts exit 6, integrity exit 4, tool errors exit 7. Each run has a unique directory and report; partial results survive external tool failure.

## Runtime Flows
Load a bounded scenario and audited artifact snapshot, validate typed cases, and create a unique run directory. Compile the audited Lean runtime and program directly. For each case, preflight bounded IR execution, run SANY/TLC and the controlled Lean proof, then collect independent statuses. Bound exhaustion skips model execution and yields UNKNOWN. Save a report atomically after the case loop, including tool failures and cancellation observed by the runner.

## State, Ownership, and Lifecycle
Invocation-local immutable configuration and locally owned temporary files. No shared mutable state. Staging is removed on failure. Completed reports persist in the requested output.

## Failure, Concurrency, and Constraints
Typed errors preserve failure; deadlines, cancellation, and output limits never count as verification success.

## Verification and Change Impact
Tests/FormalValidationTests own scenario/audit rejection. Tools/verify-distribution.py owns real positive, counterexample, bound, relocation and tamper paths. Runtime changes require updating trusted hashes and rerunning both tools.

Verification subprocesses use a 512 MiB monitored workspace budget. Lean is launched with a 1024 MiB memory limit; Java uses a 512 MiB heap and 16 MiB stack. Exceeding these budgets reports UNKNOWN and exit 6.
